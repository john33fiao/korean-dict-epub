# EPUB 변환 요구사항

이 문서는 제품·변환 동작의 공개 기준입니다. 계획, 구현, 검증, 배포와 사용자
수용을 서로 다른 상태로 기록합니다.

## 확정 기준

### 목적과 범위

- 목적은 개인이 세 사전을 처음부터 끝까지 순차적으로 읽는 EPUB 전집을 만드는
  것입니다.
- 입력은 `references/korean-dict-nikl` 서브모듈에 고정된 세 사전 XML입니다.
- 한국어기초사전 11개, 표준국어대사전 88개, 우리말샘 25개로 총 124개 XML을
  다룹니다.
- XML 1개를 EPUB 1권으로 변환하여 총 124권을 만듭니다.
- 여러 XML이나 사전을 한 권으로 합치는 기능은 현재 범위가 아닙니다.

### 원본 보존

- 원본 XML의 문서 순서와 항목 순서를 유지합니다.
- 모든 요소명, 속성명·값, 의미 있는 요소 텍스트와 tail 텍스트, 빈 요소를
  보존합니다. XML 들여쓰기에만 쓰인 공백은 데이터로 취급하지 않습니다.
- 관리 코드, 원본 링크, 미디어 URL, 다국어 번역, 문서 헤더 메타데이터도
  필터링하지 않습니다.
- 알려진 표제어·뜻풀이·예문 필드는 읽기 편하게 강조할 수 있지만, 알려진
  필드 목록이 데이터 포함 여부를 결정해서는 안 됩니다.
- XML 파서가 직접 수용하지 못하는 원본 제어문자는 누락하지 않고 가시적이며
  역변환 가능한 표현으로 보존합니다. 현재 기준선에는 `U+0008` 7개가 있습니다.
- 이미지·동영상·음성 파일은 내려받거나 EPUB에 포함하지 않습니다. XML에 있는
  URL 값만 텍스트 또는 링크로 남깁니다.

### EPUB 구성과 가독성

- EPUB 3 구조와 유효한 `nav.xhtml`, package OPF, XHTML spine을 생성합니다.
- 전자책 앱이 큰 문서를 안정적으로 열 수 있도록 항목 수와 XHTML 크기를 함께
  고려해 장을 나눕니다. 현재 기준선은 300항목 또는 약 1MiB입니다.
- 파일명은 사전 순서와 권 번호가 사전식 정렬에서도 유지되도록 0을 채웁니다.

```text
01-한국어기초사전-001-of-011.epub
02-표준국어대사전-001-of-088.epub
03-우리말샘-001-of-025.epub
```

- EPUB 메타데이터에는 사전명, 권 번호, 전체 권수, 원본 XML 이름과 안정적인
  식별자를 기록합니다.
- 모든 텍스트에 `word-break: keep-all`을 적용합니다.
- 긴 URL이나 공백 없는 문자열의 화면 넘침을 막기 위해
  `overflow-wrap: anywhere`를 함께 사용합니다.
- 본문은 `text-align: start`를 기본으로 하여 작은 화면에서 과도한 단어 간격이
  생기지 않게 합니다.

### 결과와 검증

- 원본 XML과 EPUB의 권 수는 124 대 124로 일치해야 합니다.
- 권별 항목 수, 첫·마지막 표제어와 원본 순서를 확인합니다.
- 변환기 내부 검증과 별도의 원본-EPUB 감사기가 같은 보존 결과를 확인해야
  합니다.
- EPUBCheck는 오류뿐 아니라 경고도 실패로 취급하는 엄격 검사로 실행합니다.
- 대표 첫 권과 끝 권은 EPUB을 다시 열어 XHTML 텍스트가 일반 도구에서도
  읽히는지 스모크 테스트합니다.
- 자동 검증 통과는 실제 전자책 앱에서의 시각적 QA나 사용자 수용을 대신하지
  않습니다.

### 저장소 경계

- 부모 저장소에는 EPUB 변환 로직, 로컬 웹사전 코드, 공개 문서와 서브모듈
  포인터만 커밋합니다.
- 원본 데이터는 서브모듈에서 관리하고 부모 저장소에서 직접 수정하지 않습니다.
- 생성 EPUB, 검사 보고서, 캐시, 임시 파일과 로컬 환경값은 커밋하지 않습니다.
- 에이전트 지침, repo-local 스킬, TODO, 티켓과 세션 근거는 로컬 전용으로
  유지합니다.
- 부모 저장소의 변환기 코드와 문서는 MIT License로 공개합니다. 데이터
  서브모듈과 생성 EPUB의 권리 조건은 부모 코드 라이선스와 별개입니다.

### 배포 경계

- 공개 배포 대상은 Rust CLI의 소스와 실행 바이너리, 테스트, 사용 문서입니다.
- 저장소와 릴리스 산출물에는 원본 XML, 서브모듈 작업 트리, 생성 EPUB, 검사
  보고서와 미디어 파일을 복제하거나 포함하지 않습니다. 원본 저장소를 가리키는
  서브모듈 포인터만 공개 저장소에서 관리합니다.
- 사용자는 입력 데이터를 별도로 준비하고, 도구는 로컬 입력을 읽어 로컬 출력
  디렉터리에 EPUB과 보고서를 생성합니다.
- 도구는 원본 데이터, 생성 EPUB이나 보고서를 업로드·게시·배포하는 기능을
  제공하지 않습니다.
- 생성 콘텐츠의 공개 배포는 제품 범위가 아닙니다. 도구의 MIT License는 원본
  데이터나 생성 콘텐츠를 재라이선스하지 않습니다.

### 로컬 웹사전 경계

이 경계의 아키텍처 결정은
[`ADR-0009`](decisions/0009-local-web-app-boundary.md)와
[`ADR-0010`](decisions/0010-sqlite-schema-v1.md)에 기록합니다.

- 웹사전은 EPUB 변환기와 같은 저장소에서 개발하되 별도 Rust 실행
  바이너리로 구성합니다. XML 파싱·원본 보존·감사에 필요한 공통 코드는
  공유할 수 있습니다.
- 웹사전 바이너리는 loopback HTTP server와 기본 HTML·CSS·JavaScript·아이콘·
  글꼴을 포함합니다. EPUB 변환 CLI와 웹사전 앱의 실행·배포 상태는 서로
  구분합니다.
- SQLite corpus DB는 importer가 생성하는 외부 로컬 파일입니다. 사용자는
  웹사전의 별도 설정 화면에서 기존 DB 파일을 선택하고, 앱은 SQLite 형식,
  지원 schema·migration version, 필수 metadata와 대표 조회를 검증한 뒤에만
  활성 DB로 적용합니다.
- importer의 `new`는 기존 DB나 SQLite sidecar가 있으면 거부하고, `resume`은
  동일 source commit·schema v1·`importing` 상태만 허용합니다. `rebuild`는
  명시적으로 선택한 경우에만 같은 디렉터리의 새 staging DB를 완성·검증한 뒤
  기존 경로를 원자적으로 교체합니다.
- 파일 하나의 적재는 하나의 transaction으로 확정합니다. corpus의 `ready`
  상태와 최종 count는 schema·catalog·digest/count·무결성·대표 조회 검증을
  수행하는 같은 transaction 안에서만 commit합니다.
- 단일 XML 적재는 `SourceRecord`를 순서대로 SQLite에 기록하며, 항목 경계에서
  native key·표제어·동형어 번호의 최소 projection만 분리합니다. projection
  추출 성공 여부가 원문 요소·속성·text/tail·빈 요소의 포함 여부를 바꾸지
  않습니다.
- importer는 웹앱의 machine-local active DB 설정을 읽거나 변경하지 않습니다.
- 선택한 DB는 앱 내부로 복사하지 않고 원래 로컬 경로에서 사용합니다. 선택·
  검증이나 적용이 실패하면 기존 활성 DB를 유지합니다.
- schema v1은 bundled SQLite의 `STRICT, WITHOUT ROWID` table을 사용합니다.
  원문 native key와 canonical ID를 분리하고, 손실 없는 source record·속성과
  조회 projection·관계를 별도 table에 저장합니다. migration checksum과
  schema fingerprint가 일치하는 read-only 검증 성공 결과만 활성 DB 적용의
  입력으로 사용할 수 있습니다.
- KURE model과 `llama.cpp` runtime은 웹사전 바이너리에 포함하지 않습니다.
  사용자의 PC 또는 Mac에 이미 준비된 로컬 자산을 별도 설정 화면에서
  선택·검증·적용합니다. vector index는 바이너리 밖의 재생성 가능한 로컬
  파생 파일로 관리합니다.
- 앱은 DB, model이나 runtime을 자동 다운로드·설치·업데이트하지 않습니다.
  model/runtime 검증, 적용과 embedding 재색인은 서로 다른 명시적 사용자
  동작입니다.
- 초기 웹사전은 로컬 단일 사용자용이며 공개 호스팅, 외부 network bind와
  원격 다중 사용자 운영은 범위가 아닙니다.

## 현재 설계 방향

- 주 구현은 Rust CLI로 작성합니다.
- 현재 `prototype/python/` 구현은 동작과 보존 결과를 비교하는 기준선으로
  유지하며, Rust 구현 완료로 간주하지 않습니다.
- 전체 XML을 메모리에 올리지 않는 스트리밍 파서를 사용합니다.
- XML 보존용 일반 레코드 모델과 읽기용 의미 강조를 분리합니다.
- EPUB 생성과 독립 감사는 서로 다른 코드 경로로 유지해 동일 버그가 검증까지
  통과할 위험을 줄입니다.
- 기본 입력 경로는 `references/korean-dict-nikl`, 기본 출력은 무시되는 로컬
  출력 디렉터리로 둡니다.
- 파일 단위 병렬 처리는 허용하되, 권 내부의 원본 순서는 항상 결정적으로
  유지합니다.
- Rust CLI의 현재 사전 점검 명령은 `preflight`입니다. 기본 입력
  `references/korean-dict-nikl`, 기본 출력 `outputs/rust`, 사전 선택과 1 이상의
  병렬도, 덮어쓰기·계속 실행 정책을 확인하되 XML이나 출력 파일은 건드리지
  않습니다.
- Rust 2024 edition과 MSRV 1.95를 사용합니다. CLI 사용 오류와 실행 전 경로
  오류는 서로 다른 종료 코드와 구조화된 오류 코드로 구분합니다.
- Rust 보존 계층은 원본 순서의 시작·종료·빈 요소, 속성, 요소 텍스트와 tail
  텍스트를 `SourceRecord`로 스트리밍합니다. 레코드 digest는 버전이 고정된
  길이 접두 binary token과 SHA-256을 사용합니다.
- XML 1.0 금지 제어 바이트는 허용된 PUA escape를 이용해 파싱 전 치환하고
  레코드에서 원문 문자로 복원합니다. 원본에 같은 PUA 문자가 있어도 escape
  중복 규칙으로 구분합니다.
- `inspect`는 Git 추적 XML만 파일명 순서로 catalog화하고, 사전 하나와
  1부터 시작하는 권 번호 하나의 항목 수·레코드 digest를 읽기 전용으로
  출력합니다. 미추적 XML, 중첩 경로와 심볼릭 링크는 입력에서 제외하거나
  오류로 처리합니다.
- `build`는 사전 하나와 권 번호 하나를 선택해 명세 파일명의 EPUB 3 한 권을
  생성합니다. 기본 장 제한은 완결된 300항목 또는 직렬화된 약 1MiB이며,
  한 항목 자체가 제한보다 큰 경우에만 그 항목을 나누지 않고 초과를 허용합니다.
- EPUB의 모든 source record는 순서대로 `data-kdep-kind`와 깊이, QName,
  원래 순서의 속성과 값이 있는 XHTML record로 직렬화합니다. 제어문자는
  `data-codepoint`가 있는 가시적 span으로 기록합니다. 의미 강조는 CSS class만
  추가하며 record 포함 여부를 바꾸지 않습니다.
- EPUB ZIP timestamp와 OPF 수정 시각은 고정하고 UUID v5 식별자는 사전 key와
  상대 원본 경로에서 결정적으로 생성합니다. `mimetype`은 첫 ZIP 항목이며
  무압축으로 기록합니다.
- 기존 EPUB은 기본적으로 거부하고 `--overwrite`를 명시한 경우에만 같은
  디렉터리의 임시 파일을 원자적으로 교체합니다.
- `audit`은 선택한 추적 XML과 표준 파일명의 EPUB을 직접 다시 읽고 canonical
  record digest·개수, 항목·표제어 순서와 package metadata를 대조합니다.
  변환기의 source reader, renderer와 title page digest를 감사 증거로
  재사용하지 않습니다.
- 감사 결과는 `kdep-audit-report-v1` JSON으로 EPUB과 같은 로컬 출력
  디렉터리에 원자적으로 기록합니다. 보고서에는 입력 권, 각 비교값, 실패한
  check와 재현 명령을 남깁니다.
- `batch`는 선택한 사전 또는 전체 추적 XML을 파일 단위 병렬로
  생성→독립 감사→선택적 EPUBCheck 순서로 처리합니다. 권 내부의 순서는
  병렬도와 무관하게 유지합니다.
- batch 기본 실행은 기존 EPUB을 사전 거부합니다. `--resume`은 기존 EPUB을
  감사부터 재개하고 누락 권만 생성하며, `--overwrite`는 모두 원자
  재생성합니다. 두 옵션은 동시에 사용할 수 없습니다.
- 통합 `kdep-corpus-report-v1`은 권별 생성·감사·EPUBCheck 상태를 구분합니다.
  EPUBCheck를 실행하지 않은 성공은 전체 검증 완료가 아닌 `partial`입니다.

## 남은 결정

- 전체 배치 `validate`의 세부 옵션과 통합 보고서 schema
- Python 프로토타입을 언제까지 유지할지와 제거 조건
- 개인용 생성 EPUB에 출처 안내 페이지를 선택적으로 넣을지 여부
- 실제 사용할 전자책 앱·기기와 옛한글 글꼴·줄바꿈 수용 기준
