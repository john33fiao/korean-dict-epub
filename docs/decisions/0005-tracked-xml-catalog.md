# ADR-0005: Git 추적 XML catalog와 단권 inspect

- 상태: 채택
- 날짜: 2026-07-31

## 배경

입력 디렉터리에는 upstream이 추적하지 않는 임시 XML이나 생성물이 생길 수
있습니다. 단순 glob은 이 파일을 새 권으로 포함하여 권 번호와 출력 파일명을
바꿀 수 있습니다. KDEP-002를 닫으려면 EPUB을 만들기 전에 실제 원본 한 권의
레코드와 항목 경계를 확인할 읽기 전용 흐름도 필요합니다.

## 결정

- catalog는 shell을 사용하지 않고 `git ls-files -z`를 직접 실행해 선택한
  사전의 추적 `.xml`만 발견합니다.
- Git 전역 설정은 변경하지 않습니다. 현재 명령에만 canonical 입력 경로를
  `safe.directory`로 전달하며 Windows extended path는 Git 경로 형식으로
  정규화합니다.
- Git 결과는 사전 디렉터리 바로 아래의 일반 파일인지 다시 검증합니다.
  중첩 경로, 루트 이탈, 누락 파일과 심볼릭 링크는 거부합니다.
- 파일명 정렬 후 1부터 권 번호를 부여하고 전체 권 수와 0을 채운 EPUB
  파일명을 결정합니다.
- `inspect`는 `krdict`, `stdict`, `opendict` 중 하나와 권 번호 하나를 받아
  항목 수, canonical digest와 레코드 개수를 stdout에 출력합니다.
- `inspect`는 출력 디렉터리나 보고서 파일을 만들지 않습니다.
- catalog, 권 범위와 XML 읽기 오류는 각각 `KDEP-E005`, `KDEP-E006`,
  `KDEP-E007`로 구분하고 종료 코드 3을 사용합니다.

## 이유

- Git index가 현재 입력 버전에서 추적되는 파일의 기준이므로 미추적 XML을
  구조적으로 배제할 수 있습니다.
- NUL 구분 출력은 공백이나 비ASCII 경로를 줄 단위 파싱보다 안전하게
  처리합니다.
- 단권 `inspect`는 전체 코퍼스 실행이나 출력 작성을 시작하지 않고 실제
  source record 동작을 확인할 수 있습니다.

## 결과

- catalog와 이후 build 명령에는 실행 가능한 Git과 Git worktree 형태의
  입력이 필요합니다.
- 공개 합성 fixture 테스트는 미추적 XML 제외와 결정적 정렬을 검증합니다.
- 실제 대표 원본 스모크는 각 사전 첫 권을 읽기 전용으로 실행하며, 이 결과는
  전체 124권 검증이나 EPUB·기기 QA 완료를 뜻하지 않습니다.
