# ADR-0001: Rust 주 구현과 Python 기준선 유지

- 상태: 채택
- 날짜: 2026-07-30

## 배경

입력은 약 3GB의 XML 124개이며, 약 170만 항목을 순서와 필드 손실 없이 EPUB
124권으로 변환해야 합니다. Python 프로토타입은 전체 변환과 자동 검증을
완료했지만, 앞으로 여러 번 구조와 출력 품질을 다듬고 장시간 실행 도구로
관리해야 합니다.

## 결정

- 앞으로의 주 변환기는 Rust CLI로 구현합니다.
- Python 구현은 Rust 결과가 기준선과 동등함을 입증할 때까지
  `prototype/python/`에 보존합니다.
- Python 코드를 기계적으로 그대로 옮기기보다, 요구사항의 보존 모델과 독립
  감사 경계를 Rust 모듈로 다시 설계합니다.
- Rust 구현 전환 중에도 Python 기준선이 만든 산출물과 검증 수치를 구현 완료로
  오인하지 않습니다.

## 이유

- 스트리밍 파싱과 ZIP 작성의 메모리·리소스 경계를 명시적으로 관리할 수 있습니다.
- 단일 바이너리 배포와 반복 실행이 쉽습니다.
- 강한 타입과 오류 처리가 사전별 차이, 경로와 패키징 불변식을 드러내는 데
  유리합니다.
- Python 기준선을 남기면 초기 Rust 구현의 필드 누락과 출력 회귀를 독립적으로
  비교할 수 있습니다.

## 결과

- 초기에는 두 구현이 함께 있어 중복 유지 비용이 생깁니다.
- Rust 구현은 전체 124권 보존·표준 검증과 실제 리더 QA를 통과하기 전까지
  Python 기준선을 대체하지 않습니다.
- Python 제거 시점은 별도 결정으로 남깁니다.
