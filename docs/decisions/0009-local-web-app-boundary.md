# ADR-0009: 같은 저장소의 별도 로컬 웹사전 바이너리

- 상태: 채택
- 날짜: 2026-07-31

## 배경

EPUB 변환에 사용하는 세 사전 XML을 SQLite DB로 적재하고 브라우저에서
조회하는 로컬 웹사전 트랙이 추가됐습니다. XML 입력·원본 보존·감사 계약은
기존 Rust 구현과 공유할 가치가 있지만, EPUB 변환 CLI와 웹사전 앱은 실행
목적과 의존성·수명주기가 다릅니다.

SQLite corpus DB, KURE model과 `llama.cpp` runtime은 크고 장비별 경로가
다르므로 앱 바이너리에 포함하거나 앱이 자동 설치하는 방식은 사용자가 원하는
로컬 설정 흐름과 맞지 않습니다.

## 결정

- EPUB 변환기와 웹사전은 같은 저장소에서 개발합니다.
- XML 파싱·원본 보존·감사 공통 코드는 공유하되 EPUB CLI와 웹사전 앱의
  실행 바이너리는 분리합니다.
- 웹사전 앱은 loopback HTTP server와 기본 HTML·CSS·JavaScript·아이콘·글꼴을
  바이너리에 내장합니다.
- SQLite corpus DB는 importer가 생성하는 외부 로컬 파일입니다. 사용자는
  웹사전 설정의 native file picker로 기존 DB를 선택하고, backend는 SQLite
  형식, 지원 schema version, 필수 metadata와 대표 조회를 검증한 뒤에만
  active DB로 적용합니다.
- 선택한 DB는 앱 내부로 복사하지 않고 원래 경로에서 사용합니다. 선택·검증·
  적용이 실패하면 기존 active DB를 유지합니다.
- KURE model과 `llama.cpp` runtime은 사용자의 PC 또는 Mac에 이미 준비된
  외부 로컬 자산으로 취급합니다. 설정 화면에서 선택·검증·적용하며 앱은
  다운로드·설치·업데이트하지 않습니다. vector index는 바이너리 밖의
  재생성 가능한 로컬 파생 파일로 관리합니다.
- DB 설정과 model/runtime 설정의 active 상태와 수명주기는 분리합니다.
  model/runtime 검증, 적용과 embedding 재색인은 별도 사용자 동작입니다.
- 초기 앱은 로컬 단일 사용자용이며 loopback 이외의 bind와 공개 호스팅은
  범위가 아닙니다.

## 이유

- 하나의 저장소에서 기존 무손실 입력·감사 계약을 재사용하고 두 구현의
  원본 보존 규칙이 갈라지는 위험을 줄입니다.
- 바이너리를 나누면 EPUB 변환과 웹사전 실행·의존성·검증 상태를 독립적으로
  관리할 수 있습니다.
- 대형·장비별 로컬 자산을 외부 설정으로 두면 바이너리 크기와 자동 설치
  책임을 피하고 사용자가 준비한 파일을 명시적으로 선택할 수 있습니다.
- 선택·검증·적용을 분리하고 실패 시 기존 active 자산을 유지하면 잘못된
  파일 선택이 현재 조회·검색 상태를 조용히 깨뜨리지 않습니다.

## 결과

- KWEB-002부터 KWEB-014까지의 schema, importer, launcher, runtime과 설정
  티켓은 이 저장소·바이너리·외부 자산 경계를 따라야 합니다.
- 웹사전의 구현·브라우저 QA·배포·사용자 수용은 EPUB 변환기의 검증·수용
  상태와 별도로 기록합니다.
- 향후 저장소 분리는 독립 릴리스 주기, 권한 경계나 공통 core 버전 관리 비용이
  실제로 발생할 때 별도 결정으로 검토합니다.
